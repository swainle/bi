## 三、技术实现特征（可用于原创性举证的实现细节）

区别于同类开源方案的实现路径，均可直接读代码复核：

1. **拖拽与布局**：手写 Pointer Events + 空间哈希碰撞检测 + 8px 吸附，未使用
   `react-grid-layout`、`gridstack` 等现成布局库；
2. **SQL 安全**：基于 sqlglot AST 的单语句 / 仅 SELECT / 危险函数拦截，替代正则黑名单；
   行级权限在编译期下推为 WHERE，规则损坏时 fail-closed；
3. **语义层**：前端只提交语义名（如「按店铺看总收入」），由 `semantic/compiler.py`
   编译为 `QueryObject`，物理列名不出服务端；
4. **看板文档模型**：`bi_canvas.doc`（v2.1）以「页面元素 + 页面参数 + 视图」描述看板，
   浮层复用同一渲染器，不另造「弹窗专用表」；
5. **AI 管线**：三阶段（数据清洗 → 质量校验 → 看板生成），LLM 不可用时降级本地规则。

## 四、第三方组件边界（重要）

本软件**使用**开源组件，但**不包含**其源代码：

| 类别 | 组件 | 许可证 | 与本软件的关系 |
|---|---|---|---|
| 图表渲染 | Apache ECharts | Apache-2.0 | 依赖库，按需引入，未修改 |
| 界面基础 | React、MUI、Emotion | MIT | 依赖库 |
| Web 框架 | FastAPI、SQLAlchemy、Pydantic | MIT | 依赖库 |
| 表格解析 | SheetJS (xlsx) | Apache-2.0 | 依赖库 |
| PDF/PNG 出图 | Chromium（系统级） | BSD-3 等 | 运行时调用，未随包分发 |
| 字体 | Noto Sans | OFL-1.1 | 随界面分发的字体资源 |

**判断标准**：软件是否「自研」，取决于应用层代码是否独立编写，而非是否使用开源库。
使用 MIT / Apache-2.0 等宽松许可的开源组件，不影响本软件著作权的归属，
也不构成对第三方权利的侵害。

因此本软件的正确表述是：**应用层完全自主研发，图形与界面底座采用开源组件**。
不建议对外表述为「零第三方」「100% 无开源代码」——该表述与事实不符，且在争议中
反而会被对方引用。完整清单见 [THIRD-PARTY-NOTICES.md](docs/THIRD-PARTY-NOTICES.md)。
