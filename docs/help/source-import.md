# 后台导入任务

## 创建任务

进入 **我的看板 → 数据源 → 选表接入**，勾选需要的表，点击 **创建导入任务**。

确认后系统将任务写入数据库，后台读取源表并写入本地副本，不需要保持选表弹框打开。

## 查看进度

点击 **已接入表** 标题右侧的旋转图标，打开 **后台任务**。有自己的任务正在执行或排队时，图标会旋转；任务完成后仍可点击查看结果。

| 状态 | 含义 |
| --- | --- |
| 等待导入 | 已创建任务，等待执行 |
| 正在读取 | 正在读取源表，显示已读取的行数 |
| 正在写入 | 正在写入本地副本，显示写入行数和进度 |
| 已接入 | 该表写入并登记成功，显示实际行数 |
| 导入失败 | 显示失败原因，可以重新选中该表创建任务 |

任务总进度按已处理的表数计算，单表写入进度按本批次实际读取的行数计算。读取前没有准确总行数，因此读取阶段只显示行数，不显示猜测的百分比。

关闭后台任务弹框不会停止任务。回到数据源页面可以继续查看，完成后已接入表列表会自动刷新。弹框展示当前账号创建的进行中任务和最近 20 个任务的结果。

## 避免重复接入

已接入、等待导入、正在读取、正在写入的表都会固定勾选并禁用，包括其他成员已提交的同源同名表。

搜索后的“当前全选”和 Schema 全选只会操作尚可接入的表。已禁用的表不计入确认按钮的提交数量。后端也会检查重复任务。

## 失败与数据完整性

- 一张表失败不影响同任务中其他表继续导入。
- 写入中断会回滚本批次写入；不会把半张表作为成功结果展示。
- 每张表最多接入 200,000 行。超过上限会明确失败，不会静默只导入前 200,000 行；可缩小源表范围或改用直连数据集。
- 服务重启后，等待中的任务会继续执行。已开始但中断的任务会核对接入记录：已完成登记的恢复为成功，否则标记失败，需重新创建任务。
- 有等待或执行中任务的数据源暂不能删除。
