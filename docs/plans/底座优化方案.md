# 明策BI · 底座分阶段优化方案

> 目标：把综合评分从 **67** 提升到 **85+**，通用平台能力接近 Apache Superset；
> 在电商垂直场景、语义层、中文体验、协同/模板能力上形成反超。
>
> 原则：先补短板（高并发/查询），再补产品面（分析/可视化），最后补企业化（前端测试/运维/连接器）。
> 每个阶段可独立上线、可回滚，不改业务口径、不破坏现有数据。

### 4.5 风险与回滚

- Redis 作为可选依赖：连不上时回退内存，不阻塞主流程；
- 队列上线前保留旧进程内实现，通过开关切换；
- 多 worker 先灰度 2 个 worker，再扩到 4 个。

### 4.6 P1 剩余：独立 worker 队列（已实施，默认 inline）

**要解决的问题**：异步查询目前仍在 API 进程里执行 —— API 进程被大查询拖慢/重启时，异步任务跟着受影响，
也没法单独扩容。任务表已经落 Redis（2a），差的是「执行也搬出去」。

**不变量（改崩红线）**

1. 默认行为与今天完全一致：开关 `BI_JOB_EXECUTOR=inline`（默认）时，提交仍在 API 进程执行；
2. 队列不可用（Redis 断）时，提交自动退回 inline，不能出现「任务永远排队」；
3. 任务表 / 取消 / 配额 / 慢查询全部沿用现有模块，不另起一套。

**方案对比**

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| RQ | 成熟：重试、失败队列、监控 | 新依赖 + 独立结果后端；和现有 `JobStore` 两套状态 | 备选 |
| Arq | asyncio、轻量 | 需要把同步查询包线程、依赖 async Redis | 不选 |
| **自研轻量 worker（推荐）** | 复用 `JobStore`（Redis）+ `executor`；无新依赖；行为可控 | 轮询循环要自己写（约 150 行） | 先做这个 |

**设计**

- 队列：`bi:jobq`（提交 `LPUSH`，worker `BRPOP`）；payload = job_id + QueryObject + user_id/role + attempts；
- worker 入口：`python -m app.query.async_jobs.worker`（同一镜像、不同 CMD，prod compose 新增 `worker` 服务）；
- 执行：`run(..., query_id=job.id)`，沿用语句超时、每用户配额、`bi:qrun` 登记与取消；
- 状态：worker 抢到任务先 `mark_running`；成功后 `mark_done`，异常 `mark_failed`；
  可重试错误（连接类）按 `BI_ASYNC_MAX_ATTEMPTS`（默认 2）重投，业务错误不重试；
- 取消：`/jobs/{id}/cancel` 对「已开始」直接杀 SQL（已有），对「排队中」置 `bi:jobcancel:<id>`，worker 取到后直接跳过；
- 观测：`GET /api/bi/query/jobs` 增加 `queue_len`、`workers`（心跳 key `bi:jobworker:*`，10s 刷新）。

**分期**

1. 加 worker 入口与队列开关（默认 inline，线上行为不变）；
2. prod compose 增加 worker 容器 + `BI_JOB_EXECUTOR=worker`，本地默认不启用；
3. 压测：50 个异步任务经 2 个 worker 消费，验证队列长度回落、无重复执行、取消生效。

**回滚**：把 `BI_JOB_EXECUTOR` 改回 `inline` 并停掉 worker 容器即可，数据与接口都不变。

**验收**

- inline / worker 两种模式同一条提交链路都返回 `job_id`，轮询最终 `done` 且结果一致；
- worker 被 kill 后，任务在 10 分钟内转为「已中断」而不是永久 running；
- Redis 断掉时提交仍能执行（inline 回退），只是不再排队；
- 取消排队中的任务 → 不会被执行；取消执行中的任务 → SQL 被 `pg_cancel_backend` 打断。

**实测（2026-11-13）**

- worker 未启动时提交 → `queued`，`queue_len=1 / worker_processes=0`；
- 取消排队任务 → `cancelled`，记录转 `failed（任务已被用户取消）`；启动 worker 后另一个任务转 `done`，
  被取消的那个没有被补跑，`queue_len=0 / worker_processes=1`；
- worker 模式 + Redis 指向未监听端口 → 提交直接本进程执行，最终 `done`；
- 默认 inline 模式回归：看板 107 仍 200 / 9 卡 / 0 error。
- 使用方式：`docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build`；
  回滚把 `BI_JOB_EXECUTOR` 设回 `inline` 并停掉 `worker` 容器。
