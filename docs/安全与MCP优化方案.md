## 1. 目标与原则

1. **先堵漏，再增强**：优先处理能直接把数据带出系统的通道，再谈风控与体验。
2. **默认拒绝**：权限缺失、配置失效、规则冲突时一律拒绝，不放全量。
3. **不误杀业务**：正常高频查询、批量导出只告警不封禁；只有攻击型/组合型风险才阻断。
4. **权限不重复造**：复用现有 `users / departments / roles / data_scope`，不新建平行身份体系。
5. **每阶段独立可上线**：有开关、有回滚、有回归脚本，不做大爆炸式改造。

## 5. 关键口径与边界（实施前必须遵守）

| 议题 | 结论 |
| --- | --- |
| 白名单 | 只豁免“频率风控”，**不豁免**脱敏、导出上限、RLS、审计 |
| 单指标 | 只对攻击型事件生效；业务高频只告警，不封禁 |
| 部门与令牌 | 部门不进令牌；每次请求读库，保证实时生效 |
| 令牌形态 | 每个“用户 × Agent 客户端”一条授权；不做部门级共享令牌 |
| 外发通道 | 默认白名单；外部地址仅管理员可配；禁止内网/元数据地址 |
| 前端动效 | 不整体换栈；只做局部增强，避免重写自研画布 |
| IAM | 复用现有 `users/departments`，做适配层，不新建平行体系 |
| 服务账号 | 与个人令牌分离，后台任务不借用个人授权 |

## 7. 风险与回滚

| 风险 | 应对 |
| --- | --- |
| 导出权限上线导致业务被挡 | 先灰度到非管理员角色；提供 `BI_EXPORT_ENFORCE=0` 紧急开关并记录审计 |
| 外发白名单误伤 | 白名单可配置 + 管理员豁免；失败提示明确原因 |
| 卫士 v2 误杀 | 先“只告警”运行一周，确认无误报再开启阻断；`BI_GUARD_ENABLED=0` 可关闭 |
| 令牌缩短有效期导致 Agent 中断 | 客户端实现自动刷新；灰度 30 分钟后再到 15 分钟 |
| Schema 强校验挡住存量调用 | 先记录违规日志不拒绝，一周后切换到拒绝 |
| MCP 编排事务影响性能 | 只对写工具启用事务；读工具不加锁 |

所有新开关默认值必须写进 `AGENTS.md` 与本文档，避免“代码里有、文档里没有”。
