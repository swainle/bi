# 明策BI · 商用开发规范

> 适用对象：所有参与明策BI（含前端、后端、组件、脚本、数据资产）的开发者与 AI。
> 项目定位：**面向 500+ 人企业团队的商用 BI 软件**，要求 **快速、安全、稳定、可扩展、易维护**。
>
> 本文是工程标准；日常操作规则见 `AGENTS.md`。两者冲突时，**按更严格的那条执行**。
> 架构地图与 44 个板块的边界见 `docs/BI架构与板块化扩展说明.md`；前端渲染器细则见 `docs/组件开发规范.md`。

## 0. 五条硬规则（先看这里）

| # | 规则 | 一句话判据 |
|---|---|---|
| 1 | **开源合规** | 优先 MIT；GPL / AGPL / SSPL / Commons Clause / 未知许可 **一律不引入** |
| 2 | **模块化开发** | 一块一目录；页面只做编排；模块只通过公开入口被引用 |
| 3 | **商用工程质量** | 类型完整、鉴权在服务端、失败可观测、性能按 500+ 人设计 |
| 4 | **单文件 ≤ 300 行** | 新增文件硬限制；存量文件只减不增；超了拆子文件 |
| 5 | **故障隔离** | 子页面 / 子功能改崩，不能连坐父页面、父模块和整站 |

违反以上任意一条的改动，**不予合并**；确有代价的，按 §7 走书面例外。

## 1. 开源与版权合规

> 明策BI 是**专有商用软件**（见仓库根 `LICENSE`，All Rights Reserved）。
> 使用开源件不等于可以把开源代码当成自己的代码；**许可证义务跟着分发走**。

### 1.1 许可证分级

| 级别 | 许可证 | 处理方式 |
|---|---|---|
| 🟢 绿 | MIT、ISC、BSD-2-Clause、BSD-3-Clause、0BSD、Unlicense、CC0（仅数据/文档） | 可直接用；保留版权与许可声明 |
| 🟢 绿（带义务） | Apache-2.0 | 可用；**必须保留 NOTICE / 版权声明**，修改过的文件要标注 |
| 🟡 黄 | MPL-2.0、LGPL-2.1/3.0、EPL、CDDL | 先评审再引入；只允许**动态链接 / 不修改源码**，并登记到依赖清单 |
| 🔴 红 | GPL-2.0/3.0、AGPL、SSPL、BUSL、Elastic License、Commons Clause、"非商用"、无许可证 / 未知 | **禁止引入**（含间接依赖） |

判断口诀：**MIT 优先；Apache/BSD 可用但留声明；MPL/LGPL 要登记；GPL 系一律不碰；看不清就不引入。**

### 1.2 引入任何依赖前的检查清单

- [ ] 查的是**实际安装版本**的许可证，不是官网宣传页；直接依赖与**传递依赖**都要查。
- [ ] 前端：`frontend/package.json` + `package-lock.json`；后端：`backend/requirements.txt` + 实际安装元数据。
- [ ] 许可证是 SPDX 表达式时按**全部条件**执行（例：`MPL-2.0 AND (Apache-2.0 OR MIT)` 仍需满足 MPL）。
- [ ] Apache-2.0 依赖：确认有 `NOTICE`，并在 `THIRD_PARTY_NOTICES.md` 登记。
- [ ] 是否修改过源码？修改 MPL/LGPL 文件会触发开源义务 —— 本项目原则上**不改第三方源码**。
- [ ] 依赖是否会被打包进前端 bundle / 桌面安装包 / Docker 镜像？分发形态决定义务范围。
- [ ] 是否有替代的 MIT 方案？有则优先换掉（例如图表、工具库、日期库）。
- [ ] 新增依赖必须写进 `docs/第三方依赖许可清单.md`（模板见 §8）。

### 1.3 当前基线（2026-11-17 扫描）

- 前端直接依赖（28 个）：**MIT / Apache-2.0 / ISC**，无 GPL 系。
- 后端已安装依赖：以 MIT、BSD-3、Apache-2.0、PSF 为主；灰名单 3 个：
  - `psycopg2-binary`（LGPL with exceptions）—— 动态链接、不改源码，保留声明；
  - `certifi`（MPL-2.0）—— CA 证书数据文件，不改源码；
  - `orjson`（MPL-2.0 AND (Apache-2.0 OR MIT)）—— 二进制扩展，保留声明。
- 结论：当前可商用；**新增依赖必须重新跑一遍本清单**，不能拿这份基线当永久通行证。

### 1.4 资产、数据与 AI

- **字体 / 图标 / 图片 / 地图 GeoJSON / 演示数据**同样有许可证。GeoJSON 必须记录来源与许可；
  来源不明的（例如从博客/网盘拷的 `china.json`）**不得进入商用发行物**，要换成有明确许可的源或自绘。
- 演示数据必须**脱敏或合成**，不得包含真实客户、订单、手机号、地址。
- 调用第三方 AI 模型 / API 时，遵守其服务条款；**模型权重与 API 输出不自动等于可自由商用**。
- AI 生成的代码在合并前要人工审查：确认没有整段照搬 GPL 项目或来源不明代码。

### 1.5 代码来源纪律

- 禁止从 Stack Overflow、博客、GitHub 直接复制**无许可证**的代码；要参考就重写并注明思路来源。
- 引入开源片段（即使只有 20 行）也要按依赖同等对待：记录项目、URL、许可证、版本。
- 本公司自研代码**不添加** GPL/MIT 等开源文件头；版权归公司，许可证以根 `LICENSE` 为准。

## 2. 模块化开发

### 2.1 目录契约

**前端**（按业务域，不按文件类型堆平）：

```
frontend/src/features/<domain>/
├── components/        # 该域私有的展示组件
├── hooks/             # 该域私有的状态/副作用
├── api.ts             # 只放该域接口调用
├── types.ts           # 该域类型
├── utils.ts           # 纯函数
└── index.ts           # 唯一公开出口（外部只能从这里 import）
frontend/src/pages/<Page>.tsx   # 只做路由级编排 + 组合，不写业务细节
```

**后端**（一块一目录）：

```
backend/app/<block>/
├── router.py          # HTTP 契约：参数校验、鉴权依赖、错误映射
├── service.py         # 业务编排（事务边界）
├── repository.py      # 数据访问（SQL / ORM）
├── models.py          # 表 / 领域模型
├── schemas.py         # 入参 / 出参
└── __init__.py        # 公开 API（可选 re-export）
```

### 2.2 依赖方向（只允许单向）

- 前端：`pages → features → shared(components/utils/api)`；**features 之间不互相深引**，需要共享就下沉到 `shared` 或 `components`。
- 后端：`router → service → repository → models`；**禁止 repository 反向 import router**，禁止 service 直接拼 HTTP 响应。
- 跨模块只依赖**公开入口**（`index.ts` / `__init__.py`），不要 `import "../../other-feature/internal/xxx"`。
- 兼容垫片（re-export）只用于迁移过渡，**新代码不得 import 垫片**；垫片文件只读，不在这里改逻辑。

### 2.3 新增模块的标准动作

1. 在架构文档 §2 找到它属于哪个板块；没有归属就先补板块，不要新建“杂物目录”。
2. 建目录 + 公开入口；写 `types` / 契约（前后端字段对齐）。
3. 先写服务层与失败路径，再接 UI；**不要先做界面假数据**。
4. 加测试：正常 + 空态 + 无权限 + 依赖故障。
5. 更新架构文档的映射表与更新日志。
6. 跑 §6 全部门禁。

### 2.4 反模式（出现即打回）

- 一个页面文件里同时写请求、状态、布局、弹窗、格式化（>300 行通常就是这种）。
- 两个 feature 互相 import，形成环。
- 全局可变单例承载业务状态（跨页面串数据、刷新丢状态）。
- 为了“先跑起来”把业务逻辑塞进路由函数或 React 组件体内。

## 3. 编码规范（商用 500+ 人）

### 3.1 通用

- 函数单一职责，**超过 50 行就考虑拆**；嵌套超过 3 层用早返回。
- 命名表达意图；禁止 `data / temp / handle2` 这类无信息命名。
- TypeScript 禁止裸 `any`（确实未知用 `unknown` + 收窄）；Python 公共函数必须有类型标注。
- 错误分三类：**用户输入错误（4xx）**、**依赖故障（5xx/降级）**、**程序 bug（打日志 + 告警）**，不要一律 `catch {}` 吞掉。
- 注释解释“为什么”，不复述代码；关键取舍写进更新日志或 ADR。

### 3.2 后端

- 鉴权与数据范围**在服务端每个入口现算**（`require()` / `data_scope`），不信任前端隐藏或 JWT 旧快照。
- 事务边界在 service；一次请求一个 Session；失败必须 rollback，不能把连接留在 `idle in transaction`。
- 列表接口必须分页（默认 ≤200 行）；高频查询先补索引；禁止 N+1（批量取数 / join）。
- 外部依赖（DB / Redis / LLM / Webhook）必须有超时、重试上限、失败降级；禁止无限等待。
- 审计：敏感写操作必须 `log_audit`；日志与审计里**不写密码、Token、完整连接串、身份证/手机号原文**。
- 新增端点必须同步：OpenAPI 契约、权限码、审计、测试；缺一不可。

### 3.3 前端

- 路由级 **lazy + Suspense**；页面外层必须有 `ErrorBoundary`，子区块尽量再包一层。
- 组件只通过 props 通信；跨层共享用 Context，不搞全局可变对象。
- 请求必须可取消（`AbortController`）或防竞态（请求序号）；组件卸载后不 setState。
- 高频事件（滚动/拖拽/输入）**先比较再 setState**；长列表定高/虚拟化。
- 文案遵循苹果式极简：只留必要信息，不加解释性括注。
- 表格按约定：数值右对齐、日期/ID 不当数值、长文本截断、空态明确。

### 3.4 性能（按 500+ 人团队）

- 页面首屏只加载当前路由；大依赖（ECharts、xlsx、html2canvas）不進首屏主包。
- 列表/看板超过 50 项时分页或虚拟滚动；看板卡片渲染有并发上限与缓存。
- 前端 bundle 受 `npm run budget` 约束；新增依赖前先估算 gzip 增量。
- 后端慢查询阈值 500ms；新增报表/大屏接口先做执行计划，再上线。

### 3.5 安全

- 所有写接口：认证 → 授权 → 数据范围 → 参数校验 → 业务；顺序不能反。
- 防注入：SQL 一律参数化 / 走 builder；禁止拼接用户输入。
- 防 XSS：不渲染未净化 HTML；`dangerouslySetInnerHTML` 必须经白名单净化。
- 防 SSRF：外发 URL 解析后阻断回环/内网/元数据地址（统一走 `security/outbound.py`）。
- 密钥只放 `.env` / 密钥管理，绝不进代码、日志、前端 bundle；提交前跑 `scripts/scan_secrets.sh`。

### 3.6 测试

- 新增纯函数必须单测；新增接口必须有 pytest（正常 + 权限 + 失败）。
- 修 bug 先补一个能复现的用例，再修。
- 涉及主链路的交互，补 Playwright/E2E 或在 PR 里贴逐屏截图与操作步骤。
- 测试不得依赖真实外部付费服务；外部 HTTP 必须打桩。

### 3.7 可观测

- 新增关键路径补 metrics（成功/失败/超时/耗时）；不要只写 `print`。
- 后端异常走统一 handler 落 `bi_error_log`；前端走 ErrorBoundary + `/api/report`。
- 日志带 request_id / user_id（脱敏）；能回答“谁、何时、对什么、结果如何”。

## 4. 文件规模红线（单文件 ≤ 300 行）

### 4.1 规则

| 对象 | 规则 |
|---|---|
| **新增文件** | 硬上限 **300 行**（空行/注释也计）；超了必须拆 |
| **存量文件 >300 行** | **只减不增**；本次改动不得让它变长（新增逻辑放子文件） |
| **存量文件 ≤300 行** | 改到接近 280 行时，提前规划拆分 |
| **页面/路由文件** | 目标 ≤200 行：只做编排，逻辑下沉到 hooks / 子组件 |
| **单函数** | 目标 ≤50 行；>80 行必须拆 |

### 4.2 拆分方法

- **前端页面**：`Page.tsx`（编排）→ `components/`（区块）→ `hooks/`（状态与副作用）→ `utils.ts`（纯函数）→ `types.ts`（类型）。
- **前端大组件**：按“数据 / 交互 / 展示”拆；一个弹窗一个文件；一个表单一个文件。
- **后端路由**：按资源/子域拆 `router/` 包；公共依赖进 `common.py`；保持 URL 与 OpenAPI 不变。
- **后端服务**：业务编排留 `service.py`；SQL 进 `repository.py`；纯计算进 `domain.py`。
- **拆分验收**：`tsc` / `build` / 测试 / 关键页面截图；后端加 OpenAPI 快照对照。

### 4.3 例外（必须显式标注）

以下可以超 300 行，但要在文件头 3 行内写 `FILE-LIMIT-EXEMPT: <原因>`，并在 PR 说明：

- 自动生成代码（`*.generated.*`、迁移 SQL、schema dump）；
- 种子/演示数据、fixtures、超长常量表；
- 纯类型声明文件（`.d.ts`）；
- 一次性迁移脚本（合并后归档）。

**不允许**用例外掩盖“懒得拆”。

### 4.4 执行

```bash
python scripts/check_file_limit.py          # 检查（CI 同款）
python scripts/check_file_limit.py --update # 仅用于存量基线更新，PR 必须说明原因
```

- 基线文件：`scripts/file_limit_baseline.json`（记录当前 >300 行的存量文件与行数）。
- 基线生成于 2026-11-17 大拆分之后，**基线内的文件一律视为存量**：允许变小，不允许变大；此后新增文件不得高于 300。
- 改动让某文件降到 300 以下时，跑 `--update` 把它从基线移除，防止以后又长回去。

## 5. 故障隔离原则（子功能崩，不连坐）

> 这是本规范的最终原则：**改一个子页面 / 子功能，哪怕改崩了，也不能崩掉上一级页面、模块或整个项目。**

### 5.1 前端隔离

- 每个路由一个 `ErrorBoundary`；页面内的大区块（看板卡片、图表区、数据面板）再包一层局部边界。
- 渲染前做空值/缺字段防护（`spec?.ui ?? DEFAULT_UI` 这种），**不允许在 render 里读未定义对象**。
- 子组件抛错 → 显示局部空态/错误卡，顶部导航与其它卡片继续可用。
- 异步失败不清空既有内容（保留上次结果 + 一行错误提示），避免“满屏暂无数据”。
- 懒加载 chunk 失败要有重试入口，不能白屏。

### 5.2 后端隔离

- 一次请求一个 Session，失败 rollback；**单张卡片渲染失败不影响整页其它卡片**（已有 `BI_RENDER_WORKERS` 隔离）。
- 外部依赖（数据源/LLM/Webhook）失败只降级当前功能，不抛到全局中间件。
- 长任务与轮询有超时、退避、取消；不能拖垮连接池。
- 新模块不得修改全局单例/全局中间件行为；需要横切能力时走显式依赖注入。

### 5.3 数据与权限隔离

- 数据库迁移只增不删；删列/改类型必须先双写/回填，再下线。
- 子功能只能读写自己域的表；跨域通过 service 接口，不直接写别人的表。
- 权限失败 **fail-closed**（拒绝），不能“查不到就放行”。
- 写操作幂等或带乐观锁；禁止 last-write-wins 覆盖他人编辑。

### 5.4 验收方法（每个改动至少做一次）

1. 人为让子组件抛错（或断网/返回 500）→ 父页面仍能导航、其它区块正常。
2. 让某一张卡片数据源不可用 → 其它卡片仍渲染，错误卡有提示。
3. 让某个接口 403/超时 → 页面显示局部错误，不白屏、不整页崩。
4. 改完子模块后，回归父页面 + 相邻模块（至少一条主链路）。
