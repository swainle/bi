# 组件开发规范

> 适用对象：负责「前端渲染器」的开发同学。
> 一句话：**你写的是「拿到 payload 怎么画」，不是「数据怎么来」。**
>
> 后端组件口径（`backend/app/components/spec.py / compute.py / resolver.py`）由我方维护，
> 不在本规范范围内。你需要的所有数据结构，见 [组件数据契约](./组件数据契约.md)。

---

## 0. 你能接的开发任务分三类

| 类型 | 例子 | 需要改后端吗 | 能否独立交付 |
| --- | --- | --- | --- |
| **A 类 · 视觉改造** | 柱状图换渐变圆角、KPI 卡新布局、表格新皮肤、新配色 | 不需要 | ✅ 可以 |
| **B 类 · 新图表（复用 series 结构）** | 玫瑰图、子弹图、进度条组、日历热力图 | 只需我方加 2 个常量 | ✅ 可以（PR 时说明新 kind 名） |
| **C 类 · 需要新数据形态** | 双轴组合、四象限评分、矩阵、特殊聚合 | **需要改后端** | ❌ 先提需求，由我方做后端 |

判断方法：**看 [组件数据契约](./组件数据契约.md) 里有没有现成的 payload 结构能用。** 有 → A/B；没有 → C。

## 1. 目录与文件

```
frontend/src/features/components/renderers/
├── XxxCard.tsx            # 渲染器本体（默认导出）
├── XxxCard.stories.tsx    # 必须同时交（自测 + 我方验收都靠它）
└── __fixtures__/          # 真实数据样本，只读，不要在里面对着改
```

渲染器必须是**纯组件**：同一份 props 永远渲染同一画面。默认导出。

注册（只改两行，`registry.tsx`）：

```tsx
import XxxCard from "./renderers/XxxCard";          // ① 顶部加 import
export const RENDERERS: Record<ComponentKind, Renderer> = {
  // ...
  xxx: XxxCard,                                     // ② 映射表加一行
};
```

> `ComponentKind` 的联合类型在 `types.ts` 里。**B 类任务需要我方先把它加进类型**，PR 时在描述里写清 kind 名。

## 2. Props 契约

```tsx
import type { RenderPayload, UiSpec } from "../types";

export default function XxxCard({
  payload,      // 数据，只读，结构见《组件数据契约》
  ui,           // 样式令牌：颜色/圆角/高度等只能从这里取
  compact,      // 缩略图模式（组件库卡片墙、拖拽预览用）
  onSliceClick, // 图表联动：点某个类目时回调，参数是类目的 name
}: RendererProps) { ... }
```

`RendererProps` 的完整定义在 `registry.tsx`，字段含义：

| 字段 | 用在哪 |
| --- | --- |
| `payload` | 所有组件，必用 |
| `ui` | 所有组件，样式令牌 |
| `compact` | 所有组件都要处理，见 §7 |
| `onSliceClick` | 柱 / 条 / 饼 / 漏斗 / 雷达 / 排行——**类目可点的都要接** |
| `onMore` / `onLoadAll` / `onRowClick` / `onExport` | 仅表格类 |
| `onClick` / `onTopList` | 仅指标卡 / 榜卡 |
| `onNavigate` / `currentPage` | 仅导航卡 |

**不允许自行增加 props**，也不允许在这些之外读取任何全局状态。要新能力先在 PR 里提。

## 3. 数据从哪来

**渲染器里不发请求、不读 localStorage、不读路由、不读 store。**

所有数据都通过 `payload` 传入。如果你觉得"这里需要一个接口"，说明你遇到的是 C 类任务，回来提需求。

## 4. 设计令牌（硬约束）

只能使用下面这些值。**不许硬编码十六进制颜色、不许临时造字号、不许写没来由的 px。**

| 项 | 值 |
| --- | --- |
| 字号 · 区块标题 | 11.5px / 600 / `#64748B` |
| 字号 · 正文 | 12.5px |
| 字号 · 说明 | 11.5px / `#94A3B8` |
| 字号 · 数值 | 13px / 加粗 |
| 间距 | 只用 8 的倍数：组内 12 / 14，组间 16，大块 20 |
| 细线 | `#EEF3FB` |
| 边框 | `#D8E2F5` |
| 悬浮底 | `rgba(15,23,42,0.035)` |
| 主色 | `#4F46E5`（紫） |
| 图表强调色 | `#2563EB`（蓝） |
| 圆角 · 卡片 | `"12px"` —— **必须写成字符串**（MUI 数值会 ×8） |
| 表格 | 表头浅蓝底、数值右对齐 + `tabular-nums`、日期与 ID 不当数值处理 |

配色一律走 `ui.accent`（`palette.ts` 里有色板），不要在组件里写死颜色分支。

## 5. 尺寸验收（最容易出问题的地方）

版面固定 1440 宽，卡片横向间距 16。**下面四个尺寸都要看**：

| 一排几张 | 尺寸 | 典型用途 |
| --- | --- | --- |
| 6 张 | **224 × 104** | 指标行 / 导航行 |
| 4 张 | 344 × 220 | 常用 |
| 3 张 | 464 × 260 | 常用 |
| 2 张 | 712 × 340 | 大图 |

**验收口径分两档**：

- `kpi` `nav` `banner` `rank_list` `section` `insight` `table` —— **224×104 是必测档**，
  这一档必须做到「不溢出、不折行、不看残缺」
- 图表类（`bar` `line` `pie` `combo` `heatmap` `waterfall` 等）—— **主战场是 344 以上**，
  224 档只要求「轴标签不互相压叠、不溢出卡片」，允许省略刻度

> 已知在 224 档会比较紧的是 `combo` / `heatmap` / `waterfall`（类目多、轴标签长）。
> 处理方向：标签按容器宽度自动抽稀或省略，**不允许出现文字互相压叠**。

### 5.1 窄/矮容器自动收敛（已内置，不要绕开）

平台已提供统一的收敛规则，**新组件必须复用它**，不要自己另定阈值：

```ts
import { fitChart } from "../skin/CardFit";
import { useBoxSize } from "../skin/useBoxSize";

const [boxRef, box] = useBoxSize<HTMLDivElement>();
// ...
<Box ref={boxRef} sx={{ width: "100%", height: "100%" }}>
  <ReactEChartsCore option={fitChart(option, box)} ... />
</Box>
```

口径（`skin/CardFit.tsx`）：

| 图体实测尺寸 | 行为 |
| --- | --- |
| 高 < 56px（`tight`） | 坐标轴、图例、数值标签、色阶条全部不画，只留图形（迷你图） |
| 宽 < 320px（`narrow`） | 强制 `hideOverlap`；每格宽度 < 52px 时不画数值标签 |
| 都不满足 | 原样渲染，观感与既有一致 |

**量的是「图体」不是卡片**（要扣掉标题和内边距）。必须用 `clientWidth / clientHeight`，
不要用 `getBoundingClientRect` —— 缩略图外层有 `transform: scale()`，rect 拿到的是缩放后的值。

非图表组件（排行榜、筛选栏这类纯 DOM 的）按同一口径自己按实测尺寸裁条数，
参考 `HbarCard`（按高度决定画几条）与 `FilterCard`（放不下就少放几个控件）。

规则：

- 宽度用 `100%` 跟随父容器，**不要读 `window.innerWidth`**
- 不要写死高度，父容器给多高就占多高（`height: 100%`）
- 图表用容器实测宽度做布局（`ResizeObserver` 或父级 `100%`），不要用固定 px 估算
- 文字超长用 `textOverflow: ellipsis` + `nowrap`，不要靠缩小字号硬塞

`FixtureDemo.stories.tsx` 已经把这四个尺寸摆好了，改完直接对照看（侧栏「组件验收/全类型」）。

## 6. 五种边界必须处理

| 情况 | 期望表现 |
| --- | --- |
| 空数据（`series` 为空 / `rows` 为空） | 显示一行灰色「暂无数据」，不留大白框、不报错 |
| 只有 1 条数据 | 正常渲染，不要出现「占比 100% 却很怪」的死板比例 |
| 数值跨度极大（1 和 100000） | 柱子不能一根顶天一根看不见，考虑对数轴或最小可见高度 |
| 极长文本（20 字以上类目名） | 截断 + 悬浮显示全文，不折行撑破卡片 |
| 超窄容器（224 宽） | 图例、坐标轴文字要能自动隐藏或换位，不溢出 |

这五条**每一条都要有处理**，没有就说明还没做完。

## 7. compact 模式

`compact === true` 时是缩略图模式（组件库卡片墙、拖拽浮层）：

- 不画标题、不画副标题、不画坐标轴文字、不画图例
- 保留图形主体和数据形状
- 行高、字号可以整体缩一档

要求：**缩略图要能一眼看出是什么图**。画成一片空白就等于没做。

---

## 8. 交互钩子

有"类目"概念的图（柱 / 水平条 / 饼 / 环 / 漏斗 / 雷达 / 排行榜项 / 散点）必须接 `onSliceClick`：

```tsx
onClick={() => onSliceClick?.(item.name)}
```

这是看板的**图表联动**入口（点柱子去筛其他卡片）。不接的话这个能力在这张图上就废了。

光标要变 `pointer`，hover 要有 120–160ms 的高亮过渡。

## 9. 禁止事项

1. ❌ 改 `types.ts` 里的公共类型（`ComponentKind` / `RenderPayload` / `UiSpec` / `ComponentSpec`）—— 那是跨模块契约，要改走 PR 由我方批
2. ❌ 改 `registry.tsx` 以外的公共文件
3. ❌ 在渲染器里发请求 / 读全局状态 / 用 `useEffect` 拉数据
4. ❌ 硬编码颜色、字号、圆角、间距
5. ❌ 引入新依赖（图表库、格式化库）—— 需要的话先提，我方评估体积预算
6. ❌ 用 `dangerouslySetInnerHTML` 渲染任何来自 payload 的字符串
7. ❌ 把数据写死在组件里（"示例数据"只允许出现在 `.stories.tsx`）

## 10. 开发流程

```
① 看数据契约，确认属于 A/B 类
        ↓
② 在 __fixtures__/ 里找到对应 kind 的真实 payload
   （没有就先跑一次 scripts/capture_component_fixtures.py）
        ↓
③ 写 XxxCard.tsx + XxxCard.stories.tsx
        ↓
④ npm run storybook 本地调（:6006，不连后端）
        ↓
⑤ 四尺寸 + 五边界截图自检
        ↓
⑥ npm run typecheck && npm run build-storybook
        ↓
⑦ 提 PR（模板见 §12）
        ↓
⑧ 合并后自动部署预览环境，在真实画布上再验一遍
```

本地环境：

```bash
cd frontend
pnpm install
npm run storybook        # → http://localhost:6006
```

**不需要 Python、不需要数据库、不需要后端。** 需要连真实后端联调时，单独找我要开发环境地址。
