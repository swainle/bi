# 组件数据契约

> 这份文档的作用：**让你不需要看后端源码，就知道每个组件会收到什么数据。**
> 后端实现（`spec.py / compute.py / resolver.py`）由我方维护，你不需要读它。
>
> 类型定义在 `frontend/src/features/components/types.ts` 的 `RenderPayload`，本文是它的逐项说明 + 真实样例。

---

## 0. 一句话

所有组件统一收一个 `payload`。它是**后端算完的成品数据**，不是原始行。
你的工作是「把 payload 画出来」，不要重新算占比、不要重新排序（除非契约里明确写了要你排）。

---

## 1. 所有组件共有的外层字段

无论哪种 kind，`payload` 上都带这些：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `kind` | `ComponentKind` | 组件类型，通常等于你注册的那个 |
| `title` | `string` | 卡片标题（可能为空串） |
| `subtitle` | `string` | 副标题 |
| `unit` | `string` | 单位（如「单」「元」），可能为空 |
| `ui` | `UiSpec` | 样式令牌（accent / radius / min_height / badge …） |
| `compute` | `ComputeSpec` | 计算配置（format / decimals / prefix / suffix） |
| `chart` | `ChartSpec` | 图表配置（轴标题、图例、旋转角、饼图参数…） |
| `dimension_label` | `string \| null` | 维度字段的语义名（做轴标题兜底用） |
| `metric_label` | `string \| null` | 指标字段的语义名 |
| `series_label` | `string \| null` | 「颜色（分类）」字段名，目前只有词云会用到 |
| `error` | `string?` | 有值时表示这张卡取数失败，**直接渲染一行红字即可，不要画图** |

> `sql` / `elapsed_ms` / `rls` 是调试信息，正常渲染不要显示（编辑器的调试抽屉会用到，不是你的范围）。

## 2. 数据类组件

### 2.1 通用 series 族

**适用 kind**：`bar` `hbar` `line` `area` `pie` `donut` `radar` `waterfall`

```ts
{
  kind: "bar",
  series: [{ name: "20-40元", value: 58920 }, ...],
  total: 241250,
  top_share: 0.244,        // 第一项的占比（0~1），可以直接做「TOP1 占 24.4%」的角标
  rows: [ ... ],           // 完整行（未裁剪），一般不用
}
```

| 字段 | 说明 |
| --- | --- |
| `series[i].name` | 类目名，**可能为 `null`**，渲染时兜底成 `"-"` |
| `series[i].value` | 数值，**后端已按 `top_n` 裁剪并排好序**（`binding.sort` 决定升降序） |
| `total` | 全部行（裁剪前）的合计 |
| `top_share` | 第一项 / 合计，0~1 |

**要点**

- 不要自己再排序。时间序列图（`line`/`area`）是按时间排好的，你重排会变成"按值排序"，折线图就废了。
- `total` 是全量合计，不是 `series` 之和（`series` 被裁过）。
- 分档柱状图（比如「价格带」）后端已经分好档，`name` 就是区间文案，不用你算。

### 2.2 指标卡 `kpi`

```ts
{
  kind: "kpi",
  raw_value: 26,              // 原始数值（用于比较 / 判断正负 / 上色）
  value: "26",                // 已格式化好的展示文本（带万、%、¥ 等），直接显示
  unit: "单",
  hint: "前 10 合计 1,234",   // 底部说明文案，可能为空串
  top: { enabled: true, title: "TOP 10", ... } | null,   // 右上角徽标弹窗配置
}
```

**要点**

- **显示一律用 `value`，不要自己对 `raw_value` 做格式化**（后端已经按 `compute.format` 处理过万/百分比/金额）。
- `raw_value` 只用来判断颜色（涨跌、是否超过阈值）。
- `value` 可能是 `"-"`（空数据的统一表示）。
- `top` 非空且 `enabled` 时，右上角徽标要做成可点，点了调 `onTopList()`。

### 2.3 仪表盘 `gauge`

```ts
{
  kind: "gauge",
  gauge_value: 78.4,          // 数值（画指针用）
  value: "78.4",              // 展示文本
  max: 100,                   // 刻度上限（后端按数量级取整，图表配置可以覆盖）
  unit: "分",
}
```

### 2.4 明细表 `table`

```ts
{
  kind: "table",
  rows: [ { "产品标题": "…", "日销量": 128, "主图ID": "https://…" }, ... ],
  columns: [
    { key: "产品标题", label: "产品标题", type: "text",   align: "left",  width: 0 },
    { key: "日销量",   label: "日销量",   type: "number", align: "right", width: 0 },
    { key: "主图ID",   label: "主图ID",   type: "image",  align: "left",  width: 0 },
  ],
  count: 180,                 // 总行数（不是本页行数）
  page_size: 20,
  more: true,                 // 是否显示「查看更多」→ 调 onMore()
  more_label: "查看全部",
  sortable: true,
  index_column: true,         // 是否显示行号列
  thumb: false,               // 是否显示行首缩略图
  thumb_key: "主图ID",        // 缩略图取哪一列
  detail: { enabled: false, ... },   // 行详情面板配置，enabled 才可点行
}
```

`columns[i].type` 枚举：`text` `number` `percent` `money` `image` `badge` `rank` `dual` `tag` `date`

**要点（这块踩过最多坑）**

- `width: 0` 表示「自适应」，需要由你按容器宽度分配剩余空间，不能当成 0px。
- **日期列（`2025-10-18`）和 ID 列不能当数值处理**，否则会变成 `NaN` 或加上千分位。
- 数值列右对齐 + `tabular-nums`；文本列左对齐。
- 列少（2~3 列）要铺满容器，列多要能横向滚动，两种都要看。
- `count > rows.length` 时说明被裁剪了，需要显示「共 N 条」或接「查看更多」。
- 同一个表格渲染器在**卡片内 / 查看更多弹窗 / 预览页**三处都会用到，三处都要验。

### 2.5 热力图 `heatmap`

```ts
{
  kind: "heatmap",
  matrix: {
    xLabels: ["周一", "周二", ...],
    yLabels: ["00-06", "06-12", ...],
    cells: [[0, 1, 12], [0, 2, 8], ...],   // [xIndex, yIndex, value]
    max: 42,
  },
  series: [ { x, y, value }, ... ],        // 归一化后的散点，画图用 matrix 就够
  total: 320,
}
```

### 2.6 组合图 `combo`（柱 + 线双轴）

```ts
{
  kind: "combo",
  series: [{ name: "A品牌", bar: 1200, line: 34.5 }, ...],
  bar_label: "日销量",        // 柱的图例名
  line_label: "均价",         // 线的图例名
  count: 12,
}
```

**要点**：`bar` 和 `line` 量纲不同，必须双轴（左轴柱、右轴线）。`chart.right_axis` 可关。

### 2.7 排行榜 / 榜卡 `rank_list`

```ts
{
  kind: "rank_list",
  items: [
    { name: "A品牌", value: 1280, score: 92, quad: "blue", tags: ["价格带", "高增长"] },
    ...
  ],
  count: 40,
  order: "opportunity",       // value | score | opportunity（已排好序）
  show_rank: true,            // 显示序号
  show_score: true,           // 显示分数
  show_tags: true,            // 显示标签
  quads: { blue: 8, pot: 5, red: 3, drop: 2 },   // 四象限分布（可做页脚统计）
}
```

- `quad` 枚举：`blue`（蓝海）/ `pot`（潜力）/ `red`（红海）/ `drop`（放弃）
- 三个 `show_*` 开关**必须真的生效**（关掉就不渲染），否则面板上的开关就是死按钮

### 2.8 散点图 `scatter`

**bubble / quadrant 模式**

```ts
{
  kind: "scatter",
  series: [
    { name: "A品牌", x: 120, y: 34.5, size: 890, quad: "blue", score: 92 },
    ...
  ],
  x_label: "需求量",
  y_label: "缺口",
  mode: "quadrant",           // point | bubble | quadrant
  log_x: false,
  log_y: false,
  medians: { x: 88.5, y: 21.0 },        // 仅 quadrant：象限分割线位置
  quads: { blue: 8, pot: 5, red: 3, drop: 2 },
}
```

**point 模式**：走通用 series，`series[i]` 是 `{ name, x, y, value }`，带 `total` / `top_share`。

### 2.9 词云 `wordcloud`

```ts
{
  kind: "wordcloud",
  series: [
    { name: "女装", value: 320, group: "服饰" },   // group = 颜色分类，可能没有
    ...
  ],
  total: 1200,
  top_share: 0.27,
}
```

**要点**

- `series` 已按权重从大到小排好；但「选哪些词」是按出现次数选的，**不要重排**。
- 有 `group` 时同组同色；没有 `group` 时按词名散列取色（换权重不变色）。
- 字号映射到 `value`，最小字号要保证 224 宽下仍可辨认。

### 2.10 漏斗 `funnel` / 地图 `map`

```ts
// funnel：只含正值，已按值从大到小排好、已裁剪 top_n
{ kind: "funnel", series: [{ name: "曝光", value: 12000 }, ...], total: 30000 }

// map：省份名 + 数值，已过滤非正值、最多 34 项
{ kind: "map", series: [{ name: "广东省", value: 1280 }, ...], total: 45210 }
```

- 地图的 GeoJSON 由前端自己取（`GET /api/bi/maps/china`，一天缓存），**不进 payload**
- 省份名兼容「广东省」和「广东」两种写法

## 3. 非数据类组件

这类组件不查库（`insight` / `banner` 在绑了指标时会查，但也是后端算完再给你）。

### 3.1 分节标题 `section`

```ts
{ kind: "section", index: "01", title: "榜单概况", note: "副标题/说明", icon: "bar" }
```

### 3.2 结论 / 洞察卡 `insight`

```ts
{
  kind: "insight",
  entries: [ { k: "总销量", v: "26" }, { k: "环比", v: "+12%" } ],   // {key} 占位符已由后端替换
  values: { "总销量": "26", "环比": "+12%" },
  text: "这段是 Markdown 正文，可能是空串",
}
```

### 3.3 头标卡 `banner`

```ts
{
  kind: "banner",
  kicker: "MINGZE BI",
  title: "数据看板",
  accent: "看板",            // 标题里用渐变色强调的尾段
  subtitle: "2025 年度",
  stats: [ { value: "26", unit: "单", label: "日销量", ... } ],
  tone: "sky",               // sky | indigo | teal | warm
}
```

### 3.4 导航菜单卡 `nav`

```ts
{
  kind: "nav",
  brand: "明策",
  brand_accent: "BI",        // 品牌名渐变尾段
  brand_tone: "indigo",
  items: [ { label: "概览", tone: "indigo", active: true, page: "overview" } ],
  meta: "更新于 10:30",
  badge: "正式版",
  actions: [ { label: "导出", kind: "primary" } ],
  global_nav: true,
}
```

- `active` 是后端按当前页算好的高亮；`currentPage` prop 可用于前端二次推导
- 菜单项有 `page` 时点击调 `onNavigate(page)`

### 3.5 筛选栏 `filter`

```ts
{
  kind: "filter",
  fields: [
    {
      id: "platform", label: "平台", type: "select",     // select|segment|chips|search|date
      options: [{ v: "pdd", t: "拼多多", group: "" }],
      multiple: false, placeholder: "请选择", width: 160, note: "",
      default: "pdd",
    },
  ],
  inline: true,
}
```

**要点**：筛选栏的**值不归你管**（页面层持有），你只负责渲染控件 + 把变更回调出去。
`dataset_map` / `options_map` / `split` 是分套能力，`FilterCard` 里的实现照抄即可。

## 4. 易错点清单

1. **`value` 是字符串，`raw_value` / `gauge_value` 才是数值。** 指标卡别拿 `value` 去算。
2. **日期列不是数值列。** `2025-10-18` 全是数字和横线，`Number()` 会得 `NaN`。
3. **`series` 可能为空数组**，`[0]` 之前必须判长度。
4. **`name` 可能是 `null`**（维度值为空的行）。
5. **`total` 是全量合计，不是 `series` 求和**（`series` 被 `top_n` 裁过）。
6. **数值可能是 `Decimal` 序列化后的字符串**（如 `"128.00"`），显示前兜底 `Number()` + 判 `NaN`。
7. **不要重排时间序列**（`line` / `area` / `combo` 的类目顺序有意义）。
8. **`width: 0` 是自适应，不是 0px。**

## 5. 怎么拿到真实 payload 自测

不要手敲假数据 —— 手敲的数据结构一定和真实的有偏差，会做出「Storybook 好看、画布上塌」的组件。

```bash
# 后端在跑（默认 127.0.0.1:8300）时执行
DATABASE_URL="postgresql://cavan-m4max@127.0.0.1:5432/mingcebi_dev" \
  backend/.venv/bin/python scripts/capture_component_fixtures.py
```

会在 `frontend/src/features/components/renderers/__fixtures__/` 下生成每种 kind 的真实 payload：

```
__fixtures__/
├── index.ts          # 统一导出，带类型
├── kpi.json
├── table.json
├── bar.json
└── ...
```

story 里直接引：

```tsx
import { fixtures } from "./__fixtures__";

export const Bar: Story = {
  render: () => <BarCard payload={fixtures.bar} ui={fixtures.bar.ui} />,
};
```

**数据来源是「测试数据集」（`bi_demo_sku`，已脱敏：平台A/B/C、品牌A~N、31 个省）**，不是真实业务数据，
所以这份 fixture 可以随前端包一起带走，不会泄露经营数据。

`FixtureDemo.stories.tsx` 已经把每种 kind 按四个验收尺寸摆好了，改完直接对照看。
