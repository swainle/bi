# 同一镜像分角色部署

根目录 `Dockerfile` 构建一个镜像，包含 Nginx、前端产物和 uv 锁定的 Python 环境。生产前后端分别启动，数据库和 Redis 独立运行。

| 启动角色 | 作用 |
| --- | --- |
| `frontend` | Nginx 在 8000 端口提供页面、缓存静态资源并代理 API/上传请求 |
| `backend` | FastAPI 在 8000 端口只提供 API 和上传文件 |
| `worker` | 独立执行 Redis 队列中的异步查询 |
| `app`（默认） | 保留前后端合并运行模式，由 FastAPI 提供页面和 API |

例如 `docker run --rm -p 5300:8000 -e BACKEND_URL=http://your-api:8000 mingzebi/app:local frontend`。前端角色无需数据库凭据；后端和 worker 必须配置数据库与 JWT。`BACKEND_URL` 默认为 `http://backend:8000`，DNS 默认读取容器 `/etc/resolv.conf`，可用 `NGINX_RESOLVER` 覆盖。

## 本地开发

后端在 `backend/` 下使用 uv：

```bash
cp .env.example .env    # 修改 DATABASE_URL 等配置
uv sync --locked
uv run dev             # 默认 127.0.0.1:8300，自动重载
uv run dev --host 0.0.0.0 --port 8300
uv run pytest
```

Python 默认由 `.python-version` 指定为 3.11，项目支持 3.11/3.12；系统 ODBC 驱动、Chrome 等仍需另外安装。依赖只维护 `pyproject.toml` 和 `uv.lock`，新增依赖用 `uv add`，测试依赖用 `uv add --dev`。uv 会自动准备项目虚拟环境与开发命令。

本机开发分别运行 `uv run dev` 和 `npm run dev`，保留热更新。根目录只维护一份用于部署的 Compose，不再提供单独的开发 Compose。

## 生产 Compose

在仓库根目录环境变量或 `.env` 中设置 `JWT_SECRET`（至少 32 字符）、`POSTGRES_PASSWORD`、`ADMIN_PASSWORD`：

```bash
docker compose up -d --build --remove-orphans
```

`compose.yml` 是唯一的应用部署配置。frontend、backend、worker 使用相同的 `MINGZEBI_IMAGE`（默认 `mingzebi/app:local`），只启动不同角色。前端入口为 `http://localhost:5300`；后端默认两个进程，宿主机 8300 和数据库 5433 仅绑定回环地址。前端 `VITE_SENTRY_DSN` 在构建期注入，修改后需重新构建。

`/api/livez` 为所访问角色的存活检查，前端 `/api/readyz` 代理后端就绪检查，数据库不可用返回 503。前端仍可独立提供登录页，API 不通时返回真实的 502。

API 与 worker 共享 `mingzebi_uploads`、`mingzebi_reports` 卷，数据库使用 `mingzebi_pgdata`。Redis 沿用既有缓存/队列配置；任务可靠性要求更高时需单独配置持久化和淘汰策略。不要执行 `down -v`，否则会删除业务数据卷。

本机开发与容器部署不要同时占用默认端口；需要并存时调整端口并使用不同数据库。

## 从旧配置升级

配置文件更名不会主动迁移数据。保持原 Compose 项目名（必要时 `-p 原项目名`）以继续使用原命名卷；生产部署前先备份数据库。若旧文件仍在容器可写层，重建前备份：

```bash
docker cp mingzebi-backend:/app/uploads ./mingzebi-uploads-backup
docker cp mingzebi-backend:/app/var/reports ./mingzebi-reports-backup
```

没有报表目录时可跳过第二条。新版启动后按需恢复：

```bash
docker compose cp ./mingzebi-uploads-backup/. backend:/app/uploads/
docker compose cp ./mingzebi-reports-backup/. backend:/app/var/reports/
```

## Helm

`image.repository`、`image.tag` 同时用于 frontend、backend 和可选 worker；前后端独立 Deployment，可分别调整副本和资源。Ingress 将 `/api`、`/uploads` 发往 backend，其余路径发往 frontend；前端端口转发访问也可通过 Nginx 代理 API。

```bash
helm upgrade --install mingzebi deploy/helm/mingzebi \
  --set image.repository=your-registry/mingzebi/app \
  --set image.tag=your-version \
  --set backend.existingSecret=mingzebi-secrets
```

`worker.enabled=true` 启用独立查询 worker。现有 chart 的上传目录仍为 `emptyDir`，报表未配置持久化；需要保留文件的 Kubernetes 生产环境必须先配置共享存储。

## 验证

- `uv run dev --help`、后端单测与 `uv lock --check`。
- 页面刷新成功；静态资源缓存 7 天，HTML 使用 `no-cache`；缺失 API/静态资源返回 404。
- 后端角色的页面路径返回 404；前端角色不启动数据库初始化或 Python API 进程。
- 后端停止时前端页面仍返回 200，代理 API 返回 502。
- 唯一 Compose 配置检查，Helm 默认及 worker/Ingress/HPA 变体渲染。
